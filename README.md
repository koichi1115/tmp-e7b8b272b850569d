# 近所レース（仮）

実在する住宅街の道路形状を一周する、小さなレースです。Vite、TypeScript、Canvas 2D だけで動きます。低い追従カメラから、道路、建物、土地利用をソリッド色で描きます。バックエンドはありません。レース中はコミット済み、または明示準備して端末へ保存したJSONだけを読みます。

## インストールと起動

Node.js 20.19 以降を使います。

```sh
npm install
npm run dev
```

表示されたローカル URL をデスクトップまたはスマートフォンのブラウザで開いてください。

キー操作:

- `↑` または `W` でアクセル
- `↓` または `S` でブレーキと後退
- `←`、`→`、`A`、`D` でステア
- `R` でリスタート
- `G` で全 65 本の道路中心線と境界範囲を表示
- `T` で追従カメラと俯瞰表示を切り替え
- `1` で「まちぐるま」、`2` で「こみちぐるま」に切り替え
- `B` でコース作りモードに出入り
- `E` で足元に加速パッドを設置（コース作りモード中）
- `X` で足元の加速パッドを撤去（コース作りモード中）

黄色いコースを反時計回りに走ります。4 つのチェックポイントを順番に通過し、スタートラインを越えると完走です。路面リボンから外れると加速と最高速度が落ちます。

## 固定範囲とデータ出典

コースは東京都世田谷区宮坂2丁目にあります。固定した境界範囲は、南、西、北、東の順で `35.651, 139.6415, 35.655, 139.647` です。範囲は約 496 m × 445 m です。

`src/data/neighborhood.json` は 2025-01-01 00:00:00 UTC 時点の OpenStreetMap データから生成しました。道路中心線 65 本、建物 756 棟、土地利用 2 面を含みます。データは Open Database License 1.0 の下で利用しています。

帰属表示:

画面下にも同じ帰属表示とライセンスへのリンクを常時表示します。

## 固定データを再生成する

次のコマンドは固定日時、固定範囲、固定クエリを使って固定データを作り直します。

```sh
npm run data:refresh
npm run data:verify
```

取得だけを再現する場合は次のリクエストを使います。

```sh
curl --fail --show-error \
  --data-urlencode 'data=[out:json][timeout:90][date:"2025-01-01T00:00:00Z"];(way[highway](35.651,139.6415,35.655,139.647);way[building](35.651,139.6415,35.655,139.647);way[landuse](35.651,139.6415,35.655,139.647);way[leisure](35.651,139.6415,35.655,139.647);way[natural](35.651,139.6415,35.655,139.647);way[water](35.651,139.6415,35.655,139.647););out geom;' \
  https://overpass-api.de/api/interpreter
```

生成スクリプトは上の取得元を2回試し、失敗した場合は `https://overpass.kumi.systems/api/interpreter` を2回試します。今回の取得は最初の取得元で成功しました。生成済みデータの SHA-256 は `bc60bf1ecc34b256c6e2ffddd48524cd08a0d9d12df9ab9eda63bc32dd0efda7` です。取得サービス側で履歴データの削除や修正が発生した場合は一致しないことがあります。

## データ処理と周回路の選び方

`scripts/build-fixture.mjs` は次の手順を毎回同じ順序で実行します。

1. 固定時刻の道路、建物、土地利用、余暇施設、自然地物、水域のウェイと座標列を取得します。
2. 各中心線を固定範囲内の連続区間に切り、ID 順で保存します。
3. 住宅道路、生活道路、幹線補助道路、未分類道路の OSM ノードを無向グラフにします。
4. コミット済みの固定ノード列を唯一の周回路として使います。候補列挙や面積採点によるフォールバックはありません。
5. ノード列の隣り合う各組が道路グラフの直接の辺であること、途中で同じノードを繰り返さず閉じることを検査します。
6. 次数3以上の実交差点を5地点通ることと、20度以上の曲がりを6地点以上含むことを検査します。
7. 最南端の交差点をスタートにし、最初の辺を東向きに固定します。
8. 閉じた建物ウェイを境界範囲で切り、footprint と高さを保存します。
9. 公園、草地、樹林、水面に該当する閉じたウェイを4分類へ正規化します。

現在の結果は道路グラフの12辺だけを通る424.66 mの一周です。5地点の実交差点と7地点の20度以上の曲がりを含みます。建物の高さは `height` タグ、`building:levels` と1階3 mの換算、既定の2階6 mの順で決めます。今回の内訳は `height` が0棟、階数換算が2棟、既定値が754棟です。土地利用は公園2面です。草地、樹林、水面はこの固定範囲と固定時刻では0面でした。

`scripts/verify-fixture.mjs` は全座標が固定範囲内にあることを検査します。周回の全頂点が道路辺上にあること、閉路、固定ノード列、実交差点数、曲がり数、距離、建物footprint、高さの由来、土地分類、帰属表示、ライセンス、集計値も照合します。

## 描画とレース判定

Canvas は緯度経度を固定範囲の左上基準のメートル座標へ変換します。通常表示は車の20 m後方、高さ12 mにカメラを置き、27 m先を見ます。小さな透視投影で地面とポリゴンを画面座標へ変換します。建物はfootprintから側面と屋根を押し出します。各面は奥行き順と固定ID順で並べるため、同じ入力では同じ絵になります。近距離の面は簡単なnearクリップで切ります。

すべての道路中心線を固定14 m幅のリボンにします。土地利用、道路、建物、コース表示、車の順に描きます。色は固定した手続き色だけです。`G` は全中心線を水色で重ねます。`T` の俯瞰表示では固定範囲と建物footprintを比較できます。

車両モデルには加速、ブレーキ、後退、速度に応じたステア、転がり抵抗、空気抵抗があります。最高速度は選択車両ごとに決まります。低速でも走行方向の入力中は、左右キーが毎秒 0.75 ラジアン以上で効きます。左右キーだけではその場旋回しません。路上を前進するときは、速度に応じて約 4 m から 10 m 先の中心線上の点へ車体を弱く寄せます。左右キーのステアは補助より強く、後退中は補助しません。路外では駆動力と最高速度を制限し、抵抗を増やします。進捗は中心線上の最近点から計算します。4 個の進捗ゲートを順番に通った後、進捗が終端から始端へ移ると一周を確定します。

## 既知の制約

- 道路幅は実測値ではなく、遊びやすさを優先した固定 14 m です。
- 路外判定は簡易処理です。道路リボンを越えても走れますが、駆動力と最高速度が大きく落ちます。
- ステア補助は現在進捗の少し先にある点だけを使い、目標との角度差が約 40 度以内のときだけ働きます。複雑な経路探索や自動運転はしません。
- 周回路以外の道路は街区を読むための表示です。交差点で別の道へ進んでも新しいコースにはなりません。
- 建物の大半は高さタグがないため、既定の6 mで描きます。屋根形状、穴のある面、relationは扱いません。
- 単純な奥行き順で描くため、面が交差すると前後関係を誤る場合があります。
- 建物との衝突、標識、交通規制、車両同士の衝突は扱いません。
- 最近点方式の進捗判定は、意図的な大幅ショートカットを完全には防ぎません。
- データ再生成にはネットワークが必要です。ゲーム本体の実行中はリモートリクエストを送りません。
- スマートフォン操作は画面ボタンだけです。傾き、振動、ジェスチャー操作は扱いません。
- 加速パッドは長さ6 m、幅9 mの固定寸法です。道路幅14 mの端に寄って走ると踏まずに通過できます。
- 加速が切れると速度は次の1フレームで車両の最高速度へ丸めます。緩やかに減速する演出はありません。
- パッドは周回路の路面回廊にだけ置けます。周回路以外の道路や交差点の先には置けません。

## スライス2の境界

この段階は固定した一周を、街区の立体感が読める追従表示へ広げます。商用地図、地図タイル、街路画像、写真テクスチャは使いません。編集、徒歩、飛行、自由走行範囲、複数人対戦、AI車両、音、外部ゲームエンジン、重いGIS処理も対象外です。時刻変化と乱数はありません。徒歩と設置はスライス8で加えました。飛行カメラは引き続き対象外です。

## スライス3のミニマップ

画面右下のミニマップは、固定データに含まれる道路、周回中心線、車両の位置・向きを描きます。方位は北が上で固定し、背景地図は使いません。道路と周回線は車両ごとに一度だけ別Canvasへ描いて再利用し、走行中は車両矢印だけを更新します。回転、拡大縮小、ドラッグ、地点表示、区間表示は意図的に持ちません。

## スライス5の車両と道路規則

固定データに存在する道路種別は `residential`、`secondary`、`service`、`tertiary`、`unclassified` です。通行可否と最高速度は `src/vehicles.ts` の固定表だけで決まり、乱数は使いません。

| 車両 | 通行可能な道路種別 | 通行不可 | 最高速度 |
| --- | --- | --- | --- |
| まちぐるま | `residential`、`tertiary`、`secondary`、`unclassified` | `service` | 61 km/h |
| こみちぐるま | `residential`、`tertiary`、`service`、`unclassified` | `secondary` | 40 km/h |

完走可能性は方式Aです。固定周回が使う `residential` と `tertiary` は両車両で通行できるため、どちらも同じ一周を完走できます。デモ用の差は `service` で、こみちぐるまだけが通れます。`secondary` は逆にまちぐるまだけが通れます。通行不可道路は主画面とミニマップで赤く表示します。車両が通行不可道路だけの領域へ入ると進行方向と逆へ低速で弾き返され、後退またはステアで復帰できます。車両切替はページを再読み込みせず、レースをスタート地点へ戻します。

車両規則の単体検証:

```sh
npm run vehicle:verify
```

## スライス6のタッチ操作

画面幅980px以下では、レース画面の下に左、右、ブレーキ、アクセルの4ボタンを表示します。各指をポインタIDごとに保持するため、アクセルを押したまま別の指でステアでき、片方の指を離しても残りの入力は継続します。操作領域はスクロール、拡大、文字選択、長押しメニューを抑止します。

タッチ入力はキーボードと同じ `DriveInput` に合流し、車両物理、最高速度、道路通行規則を共有します。指が1本以上触れている間はタッチを優先し、すべて離すとキーボードへ戻ります。タッチ専用の速度や物理はありません。傾き操作、振動、不可視ジェスチャー、画面構成の全面変更は対象外です。

## スライス7の自由範囲

「範囲を準備」を押すと、南・西・北・東の4座標を入力してOSM標準地図上の青枠を確認できます。地図タイルはこの準備画面を明示的に開いた時だけ読み込みます。「準備する」を押した時だけOverpassへ道路・建物・土地利用を問い合わせ、既存fixtureと同じ形へ変換して `localStorage` に1件だけ保存します。準備完了後と再読み込み後のレースは保存済みfixtureだけを使い、外部通信しません。「宮坂デモへ戻す」で保存済み範囲を削除します。

bboxは縦横80 m以上、面積0.50 km²以下です。上限を超えた場合は取得前に拒否し、範囲を狭めるメッセージを表示します。道路が0本の場合、または両車両が通れる道路グラフから120 m以上の閉路を作れない場合も準備を拒否します。宮坂デモや直線コースへ自動フォールバックしません。

閉路生成は `residential`、`tertiary`、`unclassified` の道路辺だけを使います。各道路辺を固定ID順で一度ずつ外し、両端の決定的な最短経路から閉路候補を作ります。500 mとの差、20度以上の曲がり数、道路辺ID列の順で1本を決めるため、同じfixtureからは同じ周回が生成されます。

オフラインCI用の第二fixtureは `src/data/free-range-sample.json` です。東京都杉並区高円寺北のbbox `35.701, 139.646, 35.704, 139.650` を2026-09-05に取得しました。取得元、取得時刻、完全なクエリは `src/data/free-range-sample.md` に記録しています。

```sh
npm run free-range:verify
```

通常試験は通信しません。実際のOverpass接続を含む試験は明示指定時だけ実行します。

```sh
OVERPASS_INTEGRATION=1 npm run free-range:verify
```

通常の起動と `npm run build` はネットワークを必要としません。ブラウザ検証はリモートデバッグを有効にしたブラウザを用意し、必要なら `APP_URL` と `CDP_URL` を指定して実行します。

```sh
npm run browser:verify
```

## スライス8のコース作りと加速パッド

コースへ手を入れる仕掛けは加速パッド1種類だけです。障害物は置けません。加速パッドは路面に重ねる帯で、踏んでいる間だけ速度上限を引き上げます。新しい当たり判定を増やさず、周回を物理的に塞ぐこともできないため、効果は「パッドあり」と「パッドなし」の速度とラップタイムの比較でそのまま確かめられます。

`B` キー、画面右上の「コースを作る」、タッチ操作面の「つくる」のどれでもコース作りモードへ入ります。戻るときも同じ操作か「レースへ」ボタンです。コース作りモード中は車を降りて地上を毎秒2.4 mで歩きます。移動は走行と同じ `DriveInput` を使うので、キーボードとタッチの両方がそのまま効きます。飛行カメラはありません。カメラは既存の追従カメラと同じ仕組みで、視点を歩行者の8 m後方・高さ3.4 mに置き換えただけです。足元には設置予定地の枠を出し、置ける場所は緑、置けない場所は赤で示します。

`E` または「設置」で足元に1枚置きます。向きは最寄りの周回区間の方向に合わせるので、常に進行方向を向きます。`X` または「撤去」は足元の1枚だけを消します。枚数の上限や一覧UIはありません。

### 失敗閉鎖の設置規則

設置は既定で拒否し、次の3条件をすべて満たしたときだけ受け付けます。第一に、パッドの中心が既存の周回路ポリラインの路面回廊の内側にあること、すなわち中心から周回路までの距離が道路幅の半分（7 m）に余裕1.2 mを足した8.2 m以下であること。第二に、既存のどのパッドとも中心間距離が12 m以上離れていること。第三に、ゲートの判定範囲と重ならないこと、すなわちスタート線と4つのチェックポイントの計5地点それぞれから14 m以上離れていること。ひとつでも満たさない場合は設置を拒否し、理由を画面のメッセージとして日本語で表示し、`localStorage` へは何も書き込みません。保存済みデータを読み込むときも同じ規則を先頭から順に当てはめ直し、条件を満たさないパッドは黙って捨てます。加速の強さと長さは固定定数で、倍率1.6倍、持続1.8秒、加速度26 m/s²です。加速中の上限は「車両の最高速度×1.6」と固定上限24 m/sの小さい方で、パッドを連続で踏んでも倍率は重ねがけされず、上限を超える速度は必ず24 m/sへ丸めます。まちぐるまは17 m/s×1.6 = 27.2 m/sが固定上限に当たるため24 m/s、こみちぐるまは17.6 m/sが加速時の上限です。

### 保存と復元

パッドは `localStorage` の `kinjo-race:boost-pads:v1` 1件だけに保存します。保存名の一覧や共有、書き出しはありません。保存内容にはコース識別子（地名と境界範囲）を含め、別のコースを準備した場合は読み込まずに空から始めます。再読み込みすると同じコースのパッドが復元されます。保存と読み込みは端末内で完結し、外部通信はしません。

コース作りモードから戻ると、レースはスタート地点へ戻ります。パッドはそのまま残ります。

### 検証

```sh
npm run boost:verify
npm run boost:lap
npm run build-mode:verify
```

`boost:verify` は設置規則、加速の持続と復帰、固定上限の丸め、`localStorage` の往復を単体で確かめます。`boost:lap` は同じコースを固定刻みで走らせ、パッドなし・2枚・5枚のラップタイムと最高速度を比べます。`build-mode:verify` は実ブラウザで、作成モードへの出入り、設置と撤去、路外設置の拒否、1周の完走、再読み込みの復元をキーボードとタッチの両方で確かめます。
